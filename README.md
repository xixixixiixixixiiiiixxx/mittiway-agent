# 迈特威客服 AI Agent 本地演示

这是基于工作区两份文件及迈特威官方网站资料搭建的客服框架。它演示产品咨询、型号参数、需求追问、资料溯源、参数冲突处理、售后信息收集和本地工单。企业尚未审核本示例知识，也没有接入厂家生产系统。

## 启动

要求：Python 3.10 或更高版本（只使用标准库，**无需安装任何第三方依赖**）。

```bash
git clone <仓库地址>
cd mittiway-agent
python app.py --port 8765
```

或使用启动脚本：双击本目录的 `启动演示.cmd`，或在 PowerShell 中执行 `.\start.ps1`（脚本会自动在 PATH 中查找 Python）。

浏览器访问 [http://127.0.0.1:8765](http://127.0.0.1:8765)。关闭服务窗口或按 Ctrl+C 停止。若端口被占用，可改用 `python app.py --port 8766`，访问相应地址。

> 可选：若要在答复中打开原始画册 PDF 页，请将 `2026 迈特威画册.pdf` 放在**本项目的上一级目录**（文件名保持不变）。没有该文件时其余功能不受影响，仅画册溯源链接返回提示。

运行服务只使用 Python 标准库，不需要安装额外依赖。

## 建议演示顺序

1. 问“MTW-Z15 的参数是什么？”：查看依据画册和官网组织的答复，点击出处。
2. 问“MTW-T50 的速度是多少？”：查看画册与官网的差异，不自动拼接成一套配置。
3. 新建咨询，问“我需要食品包装整线”，继续输入“用纸箱”和“尺寸400×300×300 mm，12箱/分钟”：查看多轮需求字段和待人工复核提示。
4. 问“MTW-T50 报警 E001 怎么处理？”：查看缺少报警表时的升级，不会编造报警定义。
5. 点击“创建本地模拟工单”，保存后打开“会话与工单”，查看工单编号和本地状态。
6. 在“设备知识库”搜索 `T50H`、`圆桶` 或 `折盒`，查看型号与来源。

## 已实现与当前边界

| 项目 | 当前实现 |
| --- | --- |
| 知识范围 | 26 个设备条目、33 条知识记录；核心画册内容人工转录并核对，保留出处 |
| 默认答复 | 中文二元词 BM25、精确型号匹配、规则流程、基于资料的模板组织 |
| 多轮对话 | 服务器保存型号、物料、容器、规格、节拍、报警及待补信息 |
| 参数差异 | MTW-T50 跨来源差异提示；相似型号分别保存 |
| 模拟工单 | SQLite 持久化、浏览器范围隔离、重复提交幂等；没有发送到厂家 |
| 反馈与回放 | 答复反馈、会话恢复、JSON 导出 |
| 可选模型 | 服务端 Chat Completions 兼容连接器，显式启用后使用；未以真实密钥验证 |
| 未实现的生产能力 | 企业 SSO、正式 RBAC、多租户、向量召回、模型重排、审核后台、CRM／CMMS 与真实通知 |

商业计划书仅用作开发设计输入，全文没有加入对客知识索引，也不会传给可选模型。售后缺少企业批准的手册、报警码表、SOP、维修案例及政策，因此当前演示不会生成设备操作、维修或故障诊断步骤。

## 文件结构

```text
mittiway-agent/
  app.py                    本机 HTTP 服务及接口
  agent/
    engine.py               意图、状态、追问、检索、答复和升级流程
    knowledge.py            中文 BM25、型号匹配与可见范围过滤
    llm.py                  可选模型连接器与基本输出校验
    store.py                SQLite 会话、工单、反馈和脱敏
  data/knowledge.json       可追溯的演示知识记录
  scripts/build_knowledge.py 重新构建核心知识记录
  static/                   四个页面的 HTML、CSS、JavaScript
  docs/实施方案.md           业务、架构、知识加工、流程与实施阶段
  docs/公司与资料核对.md     企业背景、产品地图、来源和差异
  docs/接口与扩展.md         接口、模型配置及生产扩展边界
  tests/                    场景与接口回归测试
  qa/                       场景回放及界面验证记录
  runtime/service.sqlite3   运行时记录；不应纳入源码分发
```

## 测试

```powershell
.\run_checks.ps1
```

当前 25 项自动检查覆盖核心场景、来源、版本差异、对话状态、会话访问范围、工单幂等与基本输入检查。`qa/scenario_results.json` 保存场景回放。测试结果只反映本地固定样例回归，不代表企业真实业务准确率、语义召回率或生产安全认证。

## 可选大模型

默认无需 API Key，不产生模型调用。确需验证真实生成时，阅读 `docs/接口与扩展.md`，将 `.env.example` 复制为 `.env`，填写企业允许使用的服务地址、模型名和密钥，再将 `AGENT_MODE` 改为 `llm` 并重启服务。

只向模型传递本轮公开检索片段。未知报警、维修、危险操作、报价、证据不足和参数冲突分支在代码中直接处理，不调用模型。连接失败或基本校验不通过时退回本地答复。数字和引用校验不能证明所有语义正确，生产上线还需要企业问题集、人审与更完整的输出评估。

## 阅读顺序

先看 `docs/公司与资料核对.md` 了解事实和缺口，再看 `docs/实施方案.md` 了解项目如何从演示进入试点，最后按 `docs/接口与扩展.md` 扩展工程接口。
