# 客服框架接口与扩展说明

## 当前工程选择

默认运行无需第三方 Python 包，使用标准库 HTTP 服务、SQLite、JSON 和浏览器原生 JavaScript。这样可以让本地演示立即运行。`http.server` 只用于本机开发，没有作为生产公网服务部署。

程序绑定 `127.0.0.1`，校验 Host 和请求 Origin；浏览器使用 HttpOnly、SameSite=Strict Cookie 关联本地会话归属。Cookie 是开发环境的浏览器归属标识，不是企业身份认证；它不提供企业 SSO、正式 RBAC 或跨租户权限模型。`role: admin` 一类客户端字段不会赋予资料权限。

静态文件使用固定路由表，项目源代码、`.env`、运行数据库及商业计划书没有静态公开路径。知识接口只返回公开演示条目。内容安全策略禁止外部脚本和跨站嵌入；界面通过转义文本构建回答，不直接执行用户或模型 HTML。

## API

所有写请求必须为 `Content-Type: application/json`。输入总长度上限为 16 KiB，单条问题最多 2000 个字符。开发演示没有流式响应。

| 方法与路径 | 用途 | 核心字段 |
| --- | --- | --- |
| GET `/api/health` | 服务可用性与模式 | `ok, mode, products, knowledge_records` |
| GET `/api/bootstrap` | 工作台初始化 | 公司、知识量、资料缺口、当前浏览器会话列表 |
| GET `/api/knowledge` | 公开示例库 | `documents, gaps`；无商业计划书全文 |
| POST `/api/conversations` | 建立当前浏览器的新会话 | 空 JSON 对象；返回服务器生成的 ID |
| GET `/api/conversations` | 列出归属当前浏览器的会话 | 最多 50 条 |
| GET `/api/conversations/{id}` | 会话与已保存答复 | 校验归属，其他浏览器返回 404 |
| POST `/api/chat` | 运行一个对话回合 | `message, conversation_id`；不传 ID 时建新会话 |
| POST `/api/tickets` | 建立本地模拟工单 | `conversation_id, category, details, idempotency_key` |
| GET `/api/tickets` | 本地工单列表 | 仅当前浏览器归属的记录 |
| POST `/api/feedback` | 保存或更新答复反馈 | `message_id, rating`，值为 `helpful` 或 `unhelpful` |
| GET `/api/export/{id}` | 导出当前会话 JSON | 校验归属，不包含模型密钥 |
| GET `/files/catalog#page=N` | 查看用户原始画册 | 保留 PDF 物理页定位；浏览器负责页码跳转 |

问答请求示例：

```json
{
  "conversation_id": "由服务端生成的会话ID",
  "message": "MTW-T50 报警 E001 怎么处理？"
}
```

问答结果包含 `answer`、`status`、`intent`、`citations`、`trace`、`slots`、`state`、`suggestions`、`mode`、`message_id`。引用包含知识记录 ID、原始来源、PDF 页／印刷页、版本和核对日期。处理轨迹用于解释检索与路由，不是模型的隐含推理过程。

`status` 的值为：`answered` 已有资料答复、`clarify` 需补字段、`handoff` 需人工处理、`conflict` 来源差异、`out_of_scope` 无可用证据或超范围。状态由服务器决定。

## 数据持久化与幂等

本地数据存放于 `runtime/service.sqlite3`，包含 `conversations`、`messages`、`tickets`、`feedback`。创建工单以“浏览器归属＋幂等键”为唯一约束。同一保存请求重试返回同一个工单，避免网络错误导致重复登记。工单状态固定为 `local_pending`，返回 `delivery: local_only`。

会话状态位于服务器，客户端不能把任意历史记录作为已授权事实直接交给工作流。每个会话的单轮更新使用锁串行处理。当前没有跨进程分布式锁、生产队列或持久化幂等聊天请求，生产扩展时需要按部署方式补齐。

常见大陆手机号和邮箱在问题进入处理和持久化前脱敏；示例不主动收集联系人信息。该正则并不覆盖所有个人或商业敏感信息，正式系统需定义字段、权限、留存、导出和删除流程。

## 连接大模型

已有默认模拟足够演示工作流。需要验证真实生成时，先确认哪些资料可发给哪个服务商，再将 `.env.example` 复制为 `.env`：

```dotenv
AGENT_MODE=llm
LLM_API_BASE=https://api.openai.com/v1
LLM_MODEL=填写已获得访问权限的模型名称
LLM_API_KEY=填写服务端密钥
```

服务地址应支持 `POST /chat/completions`、`messages` 和 JSON 对象格式输出，具体以所选服务商为准。OpenAI Chat Completions 的请求格式可参照 [官方 API 文档](https://developers.openai.com/api/reference/resources/chat)。这里只说明连接器格式，没有选择固定付费模型、价格或保留期，也没有执行真实密钥调用。

模型在可答的公开资料分支中接收当前问题和已过滤的公开证据，不接收商业计划书、数据库内容或工具执行权限。模型输出必须返回已提供文档 ID 并在文中引用；代码检查 JSON 结构、引用 ID、文内引用和新出现的数字。失败时回退本地答案。某些服务商不支持 `response_format` 时会触发回退，应在适配器中根据官方接口调整后单独测试。

这些检查不能保证事实蕴含、上下文条件或所有危险表达均正确。生产中还应做逐条事实核验、人工抽查、真实评估集、模型超时与熔断、预算和服务商数据处理条款审查。不要把环境变量中的密钥写到浏览器、日志、源码或分发包。

## 从本地检索替换为生产 RAG

保留 `KnowledgeBase.search` 的输入输出边界，将内部实现替换为授权范围内的关键词检索和向量检索。检索前解析租户和用户岗位，在数据库查询和向量召回中同时施加过滤。把相关性重排放在候选合并后，保留来源 ID、设备与版本校验。

元数据存 PostgreSQL，向量可用 pgvector，原始文件保留在企业批准的对象存储或内网文件库。关键词代码查询仍保留精确索引。索引发布与资料审核状态关联，版本撤回后不得继续命中在线服务。[pgvector 官方实现](https://github.com/pgvector/pgvector)

## 工单与系统接入

真实工单适配器至少实现三个操作：创建草稿、用户确认后提交、按授权查询受理状态。输入应是经过验证的结构化字段；服务器控制工单租户与客户归属，不能直接采用模型生成的任意 URL、数据库查询或客户 ID。

接口超时不能显示“已提交”。如果对方支持幂等键，按其约定查询或重试；如果不支持，应在本地事务／发件箱中保留待处理状态并对账。工单成功后展示真实返回的编号与状态；发送通知、分派负责人和响应时限以企业已经接入的流程为准。

订单、库存和备件查询应另设权限与字段白名单，不能借客服问答开放整库 SQL。设备控制接口、PLC 写入、安全联锁更改不应作为首期客服工具。

## 测试与发布

通过 `run_checks.ps1` 执行单元和接口测试。浏览器检查覆盖实际问答、来源窗口、资料差异、工单保存、知识搜索及响应式布局。`qa/` 下的固定样例回放用于工程回归，不是企业业务验收报告。

进入企业环境前补齐企业身份、资料授权、审核发布、备份恢复、正式服务框架、日志策略、真实资料评估和运维责任。每次知识、模型、提示词和接口变更都应可追踪并可回滚。
